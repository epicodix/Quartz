# DD-105 COLLEAGUE.SKILL: Automated AI Skill Generation via Expert Knowledge Distillation

> **arXiv**: [2605.31264](https://arxiv.org/abs/2605.31264)
> **기관**: shanghai ailab

안녕하세요, AI/ML 전문가이자 논문 리뷰어로서 COLLEAGUE.SKILL 논문을 아주 쉽고 깊이 있게 분석해 드리겠습니다. 주니어 개발자분도 직접 구현해볼 수 있을 정도로 생생한 비유와 예시를 준비했습니다.

### 논문 분석: COLLEAGUE.SKILL

### 1. 왜 이 논문이 중요한가?

기존의 AI 에이전트는 사람의 전문 지식이나 성향을 흩어진 채로만 기억할 수 있었을 뿐, 이를 검증 가능하거나 수정 가능한 형태로 정리하는 방법이 없었습니다. 이 논문은 사람의 기록(Traces)을 분석하여 AI가 바로 사용할 수 있고, 사람이 열어서 수정할 수도 있는 구조화된 스킬 패키지(Skill Package)로 자동 변환해주는 처음이자 유일한 종단 간(End-to-End) 워크플로우를 제안했다는 점이 획기적입니다.

### 2. 핵심 아이디어 쉽게 이해하기

#### 일상생활 비유: '요리사의 비법 레시피북 만들기'
이 논문의 핵심 아이디어는 "어떤 일을 잘하는 사람(동료, 전문가)이 남긴 수많은 기록을 모아서, 다른 사람도 똑같이 요리할 수 있는 완벽한 레시피북을 자동으로 만들어주는 기계"를 만드는 것과 같습니다.

기존에는 요리사가 주방에서 하는 말(Slack 대화), 손님에게 남긴 메모(이메일), 작성한 문서(PDF) 등이 여기저기 흩어져 있었습니다. 누군가 이 요리사가 어떻게 일하는지 알고 싶어도 이 모든 자료를 읽어야 했죠. COLLEAGUE.SKILL은 이 흩어진 자료를 읽어서 '이 요리사는 소스를 항상 10분간 끓인다(능력)' 혹은 '손님에게 인사할 때 반드시 눈을 맞춘다(행동 스타일)' 같은 규칙을 뽑아내 하나의 깔끔한 파일(SKILL.md)로 정리해줍니다.

#### 단계별 동작 방식
이 시스템은 크게 세 가지 단계로 작동합니다.

첫째, **수집 단계(Collectors & Parsers)**입니다. 슬랙(Slack), 이메일, PDF, 스크린샷 등 모양과 형식이 제각각인 데이터를 모두 모아서 AI가 읽기 쉬운 텍스트 형태로 정리합니다. 마치 요리 재료를 다듬어서 준비해두는 단계죠.

둘째, **증류 단계(Analyzers & Builders)**가 가장 중요합니다. 여기서 두 개의 트랙(Track)으로 나눕니다.
- **능력 트랙(Capability Track)**: 이 사람이 일을 어떻게 처리하는지, 의사결정 규칙(Heuristic)이 무엇인지를 추출합니다. 예를 들어 "코드 리뷰를 할 때는 항상 보안 이슈를 먼저 확인한다"는 내용을 뽑아냅니다.
- **행동 트랙(Behavior Track)**: 이 사람이 어떤 말투를 쓰고, 누구와 어떻게 소통하는지를 추출합니다. 예를 들어 "동료에게 실수를 지적할 때는 '우리가 ~해보면 어떨까?'라고 물으며 조심스럽게 말한다"는 패턴을 찾아냅니다.

셋째, **패키징 단계(Writer)**입니다. 추출한 내용을 바탕으로 `SKILL.md`라는 파일을 만듭니다. 이 파일은 단순한 텍스트가 아니라 AI 에이전트가 직접 읽고 실행할 수 있는 명령어 형식으로 되어 있습니다.

#### 핵심 알고리즘: 수정 가능한 구조화된 생성
이 논문에는 복잡한 수학 공식보다는 데이터의 흐름을 제어하는 파이프라인 구조가 핵심입니다. 특히 **정정 루프(Correction Workflow)** 알고리즘이 돋보입니다.
사용자가 "이 사람은 저렇게 말하지 않아"라고 피드밁을 주면, 시스템은 이를 자연어로 분석하여 해당하는 부분(능력 또는 행동)을 찾아내 `SKILL.md` 파일을 자동으로 패치(Patch)합니다. 이때 {장면, 틀린점, 올바른점} 형식의 데이터를 저장하여 다음 생성 과정에서 실수를 반복하지 않도록 학습합니다.

### 3. 실험 결과 분석

제공된 논문 텍스트 요약에는 구체적인 정량적 수치(예: 정확도 95% 등)나 기존 SOTA(State-of-the-Art) 모델과의 직접적인 성능 비교 표가 포함되어 있지 않습니다. 대신 이 논문은 시스템의 실용성과 워크플로우의 성공적인 구현에 중점을 두고 다음과 같은 정성적 성과를 보여줍니다.

#### 어느 정도에서 테스트했나?
연구진은 세 가지 구체적인 시나리오(Colleage, Celebrity, Relationship)에서 시스템을 테스트했습니다.
- **동료(Colleague)**: 실제 팀원의 슬랙 대화, 코드 리뷰 코멘트, 워크플로우 문서를 입력하여 그 사람의 업무 스타일을 모방하는 스킬을 생성했습니다.
- **유명인(Celebrity)**: 공개된 인터뷰, 저서, 긴 글 형식의 글을 입력하여 그 사람의 사고방식과 발화 스타일을 담은 스킬을 만들었습니다.
- **관계(Relationship)**: 개인적인 대화 기록을 바탕으로 특정인과의 소 interact 패턴을 담은 프리셋을 만들었습니다.

#### 주목할 만한 성과
가장 큰 성과는 **검증 가능성(Inspectability)**입니다. 기존의 페르소나(Persona) 프롬프트는 블랙박스처럼 작동하여 왜 그런 대답을 했는지 알기 어려웠지만, 이 시스템은 생성된 `SKILL.md` 파일을 사용자가 직접 열어보고 수정할 수 있게 만들었습니다. 또한, 자연어 피드백(예: "그는 이런 상황에서 저렇게 반응하지 않아")만으로도 생성된 스킬 패키지를 즉각 업데이트할 수 있는 유연한 수정 워크플로우를 성공적으로 구현했습니다.

### 4. 한계점과 향후 연구 방향

#### 저자가 언급한 한계
저자는 이 시스템이 사람을 완벽하게 시뮬레이션하는 것을 목표로 하지 않는다고 명확히 합니다. 즉, 행동의 충실도(Behavioral Fidelity)가 100%라는 보장은 없으며, 생성된 스킬은 원본 사람의 대체물이 아니라 "제한된 아티팩트(Constrained Artifact)"로 간주되어야 합니다. 또한, 소스 데이터의 권리(Source Rights)와 동의(Consent) 문제, 특히 개인적인 기록을 사용할 때의 윤리적 문제를 기술적인 시스템만으로는 완전히 해결할 수 없음을 인정합니다.

#### 개선 가능한 점
향후 연구에서는 더 정교한 피드백 루프를 통해 스킬의 정확도를 높이고, 스킬 패키지를 공유하고 거래할 수 있는 갤러리(Gallery) 생태계 구축이 필요합니다. 또한, 특정 도메인(예: 법률, 의료)에 맞춘 정밀한 증류 프롬프트를 개발하여 전문성을 더욱 강화할 수 있을 것입니다.

### 5. 실무 적용 가능성

#### 어디에 바로 적용 가능?
- **기업 내부 지식 관리(KM)**: 시니어 개발자나 매니저가 퇴사하더라도 그들의 업무 처리 방식과 커뮤니케이션 스타일을 '스킬'로 남겨 후배들이 AI 에이전트를 통해 그들의 노하우를 계속 활용할 수 있습니다.
- **고객 지원 센터**: 최고 상담원의 응대 패턴을 스킬로 만들어 AI 상담 봇에 적용하면, 기계적이던 답변이 훨씬 인간적이고 전문적으로 변할 것입니다.
- **개인 비서 서비스**: 사용자의 과거 대화 기록을 분석하여 사용자처럼 메일을 작성하거나 일정을 잡아주는 하이퍼 퍼스널라이즈드 AI 비서를 만들 수 있습니다.

#### 필요한 리소스
- **데이터**: 대상이 되는 사람의 텍스트 기록(슬랙, 이메일, 문서 등)이 충분히 확보되어야 합니다.
- **LLM 모델**: GPT-4o나 Claude 3.5 Sonnet 같은 고성능 언어 모델에 접근할 수 있는 API 키가 필요합니다. 데이터를 분석하고 구조화하는 데 큰 언어 모델의 추론 능력이 필수적이기 때문입니다.
- **스토리지**: 생성된 스킬 패키지와 원본 데이터를 저장할 로컬 파일 시스템 또는 클라우드 스토리지가 필요합니다.

### 6. 이 논문을 이해하기 위한 사전 지식

- **LLM Agent (Large Language Model Agent)**: 단순히 텍스트를 생성하는 것을 넘어, 스스로 생각하고 도구를 사용하여 문제를 해결하는 AI 시스템을 말합니다.
- **Knowledge Distillation (지식 증류)**: 크고 복잡한 모델(또는 전문가)이 가진 지식을 추출하여 더 작고 효율적인 모델(또는 구조화된 파일)로 옮기는 기술입니다.
- **Prompt Engineering (프롬프트 엔지니어링)**: 언어 모델에게 원하는 결과를 얻기 위해 입력하는 텍스트(프롬프트)를 최적화하는 기술입니다.
- **Markdown**: 텍스트에 서식을 쉽게 입힐 수 있는 경량 마크업 언어로, 이 논문에서는 스킬 패키지의 표준 포맷으로 사용됩니다.
- **Persona (페르소나)**: AI가 대화할 때 맡게 되는 인격, 역할, 성격 등을 설정하는 것을 말합니다.
- **Traces (흔적/기록)**: 사용자의 행동, 대화, 문서 작성 등 디지털 세상에 남는 모든 기록 데이터를 의미합니다.
