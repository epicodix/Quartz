# 논문 리뷰: Code as Agent Harness

## 1. 왜 이 논문이 중요한가?

기존의 연구들은 대규모 언어 모델(LLM)이 코드를 작성하는 능력에만 집중하여, 코드를 단순한 텍스트 생성 결과물로 취급하는 경향이 있었습니다. 이로 인해 생성된 코드가 실제 환경에서 어떻게 실행되고, 에이전트가 이를 통해 스스로 생각하고 행동하는 과정은 체계적으로 다뤄지지 못했습니다. 이 논문은 코드를 단순한 출력물이 아니라 에이전트가 추론하고, 행동하고, 환경을 모델링하며, 실행을 통해 검증하는 운영 체제(Operational Substrate)로 재정의합니다. 즉, 코드를 에이전트를 감싸고 제어하는 하네스(Harness)로 정의하여, LLM이 상태가 없는 모델에서 장기적인 작업을 수행할 수 있는 강건한 에이전트로 진화할 수 있는 통합된 프레임워크를 제시합니다.

## 2. 핵심 아이디어 쉽게 이해하기

### 일상생활 비유: '자동차와 운전자'
기존의 LLM 코드 생성은 마치 '운전자가 설계도면을 종이에 그리는 것'과 같습니다. 아무리 정교한 설계도면(코드)을 그려도, 그것이 실제 자동차가 아니라면 바퀴를 굴려갈 수 없습니다. 이 논문이 제안하는 'Code as Agent Harness'는 운전자(LLM)가 실제로 자동차(코드 하네스)에 탑승하여 핸들을 조작하고, 엑셀을 밟고, 내비게이션을 보면서 목적지로 이동하는 시스템입니다. 여기서 코드는 단순히 보여주는 설계도가 아니라, 운전자의 의지를 실제 움직임으로 바꿔주는 엔진, 바퀴, 연료 장치의 역할을 수행합니다.

### 단계별 동작 원리
이 시스템은 크게 세 가지 층(Layer)으로 나뉘어 작동합니다. 첫 번째는 인터페이스 층으로, 운전자가 자동차의 제어 장치와 연결되는 부분입니다. LLM이 생성한 코드를 통해 외부 도구나 환경과 상호작용합니다. 두 번째는 메커니즘 층으로, 자동차의 운전 로직입니다. 에이전트가 계획을 세우고(Planning), 과거의 주행 경로를 기억하며(Memory), 상황에 맞는 도구를 사용하고(Tool Use), 생긴 문제를 교정하는(Control) 과정이 포함됩니다. 마지막으로 확장 층에서는 여러 대의 자동차가 서로 통신하며 교통 상황을 조절하는 것처럼, 여러 전문 에이전트들이 코드를 공유하며 협업하는 멀티 에이전트 오케스트레이션을 다룹니다.

### 핵심 알고리즘 및 구조
이 논문은 특정한 수학적 공식보다는 시스템 아키텍처와 제어 흐름을 강조합니다. 핵심은 상태(State)와 코드의 상호작용입니다. 에이전트는 정적인 모델(Model)에서 판단(Judgment)을 내리고, 이를 코드라는 매개체를 통해 가변적인 상태(Mutable State)를 변경합니다. 하네스 인프라는 이러한 상태 변환을 안전하게 관리하고, 에이전트가 작성한 코드가 신뢰할 수 있는지 검증(Verification)하는 정책과 권한 계층을 제공합니다. 즉, 코드를 실행 가능한 매체로 사용하되, 이를 감싸고 있는 하네스 시스템이 전체 작업의 안정성을 보장하는 구조입니다.

## 3. 실험 결과 분석

### 벤치마크 및 테스트 환경
이 논문은 소프트웨어 공학(SWE) 전반, 특히 저장소(Repository) 수준의 엔지니어링 작업을 중심으로 다양한 기존 시스템을 분석하고 재구성했습니다. 주로 경쟁 프로그래밍(Competitive Programming)부터 복잡한 소프트웨어 개발 생태계에 이르는 광범위한 환경에서 기존 단일 에이전트 시스템과 제안하는 프레임워크의 효율성을 비교 분석했습니다.

### 기존 SOTA(State-of-the-Art) 대비 성능
단일 에이전트 방식은 맥락 창(Context Window)의 제한과 전문성 부족으로 인해 대규모 코드베이스를 처리하는 데 한계가 있었습니다. 반면, 이 논문에서 제안하는 멀티 에이전트 오케스트레이션 방식(예: ChatDev, MetaGPT, AgentCoder)을 적용할 경우, 작업을 건축가, 프로그래머, 테스터, 검토자 같은 역할로 분담함으로써 문제 해결 능력이 획기적으로 향상됨을 보여줍니다. 특히 단일 에이전트가 자가 수정(Self-correction)하기 어려운 오류들을 독립적인 검토 채널을 통해 30% 이상 더 정확하게 탐지하고 수정한다는 결과가 보고되었습니다.

### 주목할 만한 성과
가장 인상적인 점은 코드가 단순한 산출물이 아니라 에이전트 간의 공유 기질(Shared Substrate)이 된다는 점입니다. 에이전트들이 공유하는 코드를 통해 서로의 생각을 확인하고 수정함으로써, 전체 시스템의 모듈성(Modularity)과 검사 가능성(Inspectability)이 크게 개선되었습니다. 이는 복잡한 장기 작업(Long-horizon Execution)에서 에이전트의 신뢰성을 높이는 결정적인 역할을 합니다.

## 4. 한계점과 향후 연구 방향

### 저자가 언급한 한계
동적으로 작성된 코드가 하네스 인프라 자체를 완전히 대체할 수는 없습니다. 즉, 에이전트가 생성한 코드가 아무리 똑똑해도, 이를 감싸는 보안 정책, 샌드박스 경계, 권한 관리와 같은 인간이 설계한 인프라는 여전히 필수적입니다. 코드를 실행 가능한 매체로 신뢰하기 위해서는 모델의 판단력과 인간이 설계한 안전장치가 조화를 이루어야 한다는 점이 강조되었습니다.

### 개선 가능한 점
향후 연구에서는 에이전트가 작성한 코드의 신뢰성을 어떻게 더욱 보장할 것인가(예: 형식적 검증 Formal Verification)와 대규모 멀티 에이전트 시스템에서의 효율적인 통신 프로토콜 설계가 중요한 과제로 남아 있습니다. 또한, 코드 하네스가 확장될 때 발생할 수 있는 보안 취약점을 최소화하는 기술 개발도 필요합니다.

## 5. 실무 적용 가능성

### 어디에 바로 적용 가능?
이 개념은 자동화된 소프트웨어 개발 도구, 복잡한 데이터 분석 파이프라인, 로봇 공학 제어 시스템 등에 즉시 적용할 수 있습니다. 특히, 대규모 레거시 코드를 유지보수하거나 새로운 기능을 통합하는 '개발자 에이전트'를 구축할 때 필수적인 아키텍처가 될 것입니다.

### 필요한 리소스
이 시스템을 구축하려면 강력한 추론 능력을 가진 LLM(예: GPT-4급 모델)과 코드를 안전하게 실행할 수 있는 격리된 실행 환경(Sandbox, Docker 등)이 필요합니다. 또한, 에이전트 간의 대화 기록과 코드 실행 결과를 저장할 수 있는 대용량 벡터 데이터베이스 및 상태 저장소가 요구됩니다.

## 6. 이 논문을 이해하기 위한 사전 지식

- **대규모 언어 모델(LLM)**: 방대한 텍스트 데이터로 학습되어 자연어 이해 및 생성 능력을 갖춘 인공지능 모델입니다.
- **에이전트(Agent)**: 사용자의 목표를 달성하기 위해 환경을 인지하고, 판단하고, 독립적으로 행동하는 자율적인 시스템입니다.
- **하네스(Harness)**: 시스템이나 모델을 제어하고 관리하기 위해 외부에서 제공하는 소프트웨어 계층이나 장치를 의미합니다.
- **프롬프트 엔지니어링(Prompt Engineering)**: 언어 모델이 원하는 결과를 내도록 입력하는 자연어 명령어를 최적화하는 기술입니다.
- **멀티 에이전트 시스템(Multi-Agent System)**: 여러 개의 에이전트가 서로 협력하거나 경쟁하며 문제를 해결하는 분산 시스템입니다.
- **샌드박스(Sandbox)**: 외부 시스템의 보안을 위협하지 않도록 프로그램을 격리된 환경에서 실행해 테스트하는 보안 기법입니다.
- **체인 오브 사고(Chain of Thought)**: 모델이 복잡한 문제를 해결할 때 중간 단계의 추론 과정을 단계적으로 보여주는 사고 방식입니다.
