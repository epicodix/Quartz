2. 집중 영역 / 시간 소모 포인트

생산적 작업

  • 다차원 팁 생성 프롬프트 설계: 단일 액션 방식에서 solutions(1순위/대안/최후수단), validity, verified_by 필드를 포함하는 구조로 업그레드하여 데이터 퀄리티 향상.
  • Public Session 기능 구현: 로그인 없이 일시적으로 연락처를 공유할 수 있는 백엔드(store/session.go, handlers/session.go) 및 프론트엔드 로직 구현.
  • 백엔드 프롬프트 로직 전면 개선: build_info_answer, build_chunk_prompt, classify_query 등 핵심 함수의 프롬프트를 ‘백과사전식 설명’에서 ‘문화적 경험 제공(낯섦 → 새로운 경험)’ 방향으로 재설계하고, 페르소나를 ‘처음 만난 한국인 친구’로 구체화함.
  • 데이터 정제 및 병합: 총 96개의 팁 데이터를 확보하고 인덱싱하며, 구형 데이터를 제거하여 신뢰도 높은 데이터셋 구축.

삽질/시간 소모 포인트

  • Qdrant 연결 에러: index_qdrant.py 실행 시 ConnectionRefusedError 발생. Docker 데몬이 꺼져 있어 docker start qdrant-locally 명령으로 해결.
  • 프론트엔드 훅 배치 오류: CardViewPage.js 수정 중 useState/useEffect가 조건문 뒤에 위치하여 빌드 에러 발생, 훅을 상단으로 이동하여 수정.
  • 모델 한계 보완 작업: GLM 모델의 복합 추론 및 섬세한 문화 해석 능력 부족을 프롬프트 엔지니어링으로 커버하려고 시도한 부분.

4. 해결한 문제와 인사이트

해결한 문제

  • 팁 데이터 퀄리티 저하: 단일 액션 및 가정에 기반한 구형 데이터 대신, solutions(1순위/대안/최후수단), validity, verified_by 필드를 포함하는 다차원 프롬프트를 도입하여 신뢰도 높은 데이터 생성.
  • 연락처 공유의 편의성 vs 보안: 로그인 사용자에게만 제공되던 연락처를, 소유자가 설정한 시간 동안 비회원에게도 공개 가능하도록 하는 Public Session 기능(백엔드: 세션 활성화/비활성화 API, 프론트: 카운트다운 토글 UI) 구현.
  • Qdrant 인덱싱 실패: Docker 컨테이너(qdrant-locally)가 중지되어 발생한 ConnectionRefusedError를 해결하여 96개 팁 인덱싱 완료.
  • 건조한 AI 답변 톤앤매너: 백엔드 프롬프트를 개선하여 단순한 정보 제공을 넘어 사용자가 “해보고 싶다”는 느낌을 갖도록 유도하는 로직 적용.

인사이트

  • Fail-Safe 설계: 세션 확인 로직에서 에러 발생 시 무조건 연락처를 잠금(locked) 처리하여 개인정보 노출 방지. 조회수 증가는 비동기(goroutine)로 처리하여 응답 속도 저하 방지.
  • 데이터 구조의 UI 반영: 단순 텍스트 팁에서 solutions 계층 구조와 검증 배지(validity, verified_by)를 UI(카드 상세 및 피드)에 시각화하여 사용자에게 신뢰도 전달.
  • 모델 생성 로직의 한계와 보완: 복합 추론이나 깊이 있는 문화 해석 능력은 결국 기본 모델(언어 모델)의 성능에 의존적임을 인지. GLM-4.7의 한계를 명시하고, 궁극적으로는 GPT-4나 Claude급 모델로의 교체 필요성 도출.
